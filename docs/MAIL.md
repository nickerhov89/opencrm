# Почта в сделках

OpenCRM забирает письма подключённых ящиков по IMAP, кладёт их в ленту сделки рядом с примечаниями и даёт ответить прямо из карточки через SMTP того же ящика. Ящики подключает администратор: **Настройки → Почта**.

## Подключение ящика

Перед сохранением OpenCRM входит в ящик по IMAP и SMTP. Если вход не удался, ящик не сохраняется, а в ответе видна причина. После подключения загружается история за 60 дней (можно указать от 1 до 365), дальше новые письма забираются каждые две минуты. Кнопка «Синхронизировать» запускает синхронизацию сразу.

Есть два способа входа.

**IMAP и SMTP с паролем приложения.** Подходит для Gmail, Яндекса, Mail.ru, Outlook и своих серверов. Укажите серверы, порты и пароль приложения: обычный пароль почтовые сервисы по IMAP чаще всего не принимают. Логин по умолчанию — адрес ящика. Режим TLS выбирается по порту:
- IMAP: 143 — STARTTLS, остальные порты — TLS сразу (обычно 993);
- SMTP: 25, 587 и 2525 — STARTTLS, остальные порты — TLS сразу (обычно 465).

**Google Workspace через сервисный аккаунт.** OpenCRM входит в ящик от его имени (XOAUTH2), пароль ящика не нужен. Что сделать:

1. В Google Cloud создать сервисный аккаунт и JSON-ключ к нему.
2. В Admin Console домена: Безопасность → Доступ к данным и управление ими → Управление API → Делегирование на уровне домена. Добавить Client ID сервисного аккаунта со scope `https://mail.google.com/`.
3. В OpenCRM вставить JSON-ключ целиком и указать адрес ящика.

Делегирование действует только на ящики домена, где оно настроено. Ящик другого домена Google, даже в той же организации, вернёт `unauthorized_client`, пока делегирование не добавлено и там.

### С сервера, без вставки ключа в браузер

`scripts/mail-add.mjs` делает то же, что форма в настройках: проверяет вход по IMAP и SMTP, шифрует ключ или пароль и пишет запись в журнал безопасности. Секрет читается из файла и нигде не печатается. Файл положите во временную папку с правами 0600 и удалите сразу после запуска.

```bash
docker compose -p opencrm cp /root/sa.json opencrm:/tmp/sa.json
docker compose -p opencrm exec opencrm node scripts/mail-add.mjs --email sales@company.ru --google-sa-file /tmp/sa.json --name "Отдел продаж"
docker compose -p opencrm exec opencrm rm /tmp/sa.json
```

Параметры:
- `--password-file FILE` вместе с `--imap-host`, `--smtp-host` (порты `--imap-port`/`--smtp-port`, логин `--username`) — вход по паролю приложения; из файла берётся первая строка;
- `--history-days N` — сколько дней истории загрузить при первой синхронизации;
- `--update` — заменить ключ или пароль уже подключённого ящика;
- `--sync` — сразу прочитать почту, не дожидаясь сервера.

## Хранение секретов

Пароли и ключи сервисных аккаунтов хранятся в базе в зашифрованном виде (AES-256-GCM). Ключ шифрования берётся из `OPENCRM_SECRET_KEY`. Если переменная не задана, при первом подключении ящика создаётся случайный ключ в файле `secret.key` рядом с каталогом вложений: в Docker это `/app/data/secret.key`, том `opencrm_data`, права 0600. Путь можно задать в `OPENCRM_SECRET_FILE`.

В резервную копию (дамп базы и вложения) ключ не входит, поэтому украденная копия не раскрывает пароли ящиков. После восстановления на новый сервер без старого ключа синхронизация остановится с ошибкой «ключ шифрования сменился»: укажите пароли или ключи заново («Сменить пароль»). Письма при этом не теряются.

API и интерфейс пароли и ключи не возвращают. Для сервисного аккаунта видно только его `client_email`.

## Какие письма читаются

- **Gmail и Google Workspace:** папка «Вся почта» (`\All`), то есть входящие и отправленные вместе. Спам и корзина не читаются.
- **Другие серверы:** INBOX и папка отправленных (`\Sent`).
- **Черновики** пропускаются.

Синхронизация идёт по UID по нарастающей и помнит последний UID каждой папки. Если у папки сменился UIDVALIDITY, папка перечитывается за период истории без дублей.

У письма сохраняются:
- поля From, To, Cc, Reply-To, Subject, Message-ID, In-Reply-To, References и дата;
- текст: из HTML без картинок и ссылок, до 200 000 символов;
- список вложений: имя, тип и примерный размер. Сами файлы не скачиваются: из письма читаются первые 2 МБ, список вложений берётся из структуры письма (BODYSTRUCTURE).

Одно письмо хранится один раз, даже если оно лежит в двух подключённых ящиках: дубли схлопываются по Message-ID.

Направление письма определяется в сделке. Входящее — письмо от клиента: From совпадает с e-mail контакта сделки или её компании либо на том же домене (коллега клиента). У бесплатных почтовых доменов (gmail.com, mail.ru, yandex.ru и подобных) считается только точный адрес. Остальные письма сделки исходящие: подключённые ящики, ящики рассылки, менеджеры. Поэтому письмо пересылки с ящика рассылки клиенту — исходящее, хотя пришло копией. Письмо без сделки исходящее, только если отправлено с подключённого ящика. При привязке к сделке направление пересчитывается.

## Привязка к сделке

1. **По ветке.** In-Reply-To или References указывают на письмо, которое уже привязано к сделке. Тогда письмо попадает в ту же сделку. Так ловится, например, ответ менеджера на письмо рассылки, где клиента среди получателей нет.
2. **По адресу.** From, Reply-To, To или Cc совпадает с e-mail контакта сделки (основного или связанного) или её компании. Адреса подключённых ящиков не учитываются. У контакта может быть несколько адресов через запятую — так их сохраняет перенос из amoCRM. Порядок выбора:
   - сделка, найденная через контакт, важнее сделки через компанию;
   - открытая сделка важнее закрытой;
   - среди равных берётся последняя изменённая.

3. **По теме.** Если ни ветка, ни адрес не нашли сделку (например, в ветках Instantly References бывают неполными), берётся тема без Re:/Fwd: и меток вида [#XXXXXXXX]. Среди писем со сделкой за 60 дней до письма ищутся письма с той же темой и тем же собеседником — хотя бы один общий адрес, кроме подключённых ящиков. Письмо привязывается, только если все такие письма из одной сделки. Если сделок несколько (одна тема рассылки у разных клиентов), письмо остаётся непривязанным.

Письма без сделки хранятся непривязанными. При каждой синхронизации письма за период истории проверяются заново: если позже появился контакт с этим адресом или письмо той же ветки нашло сделку, письмо привяжется само. Последние 50 непривязанных писем видны в **Настройки → Почта**, там их можно привязать к сделке по номеру вручную.

Права: настройки почты и непривязанные письма видит только администратор. Письма сделки видят те, кому видна сделка. Отвечать могут те, у кого есть право изменять сделки.

## Ответ из карточки

Под каждым письмом есть кнопки «Ответить» и «Ответить всем». Ответ уходит через SMTP ящика, в который пришло письмо.

- **Кому:** Reply-To или From исходного письма. Если отвечаем на своё отправленное письмо — его получателям, как в почтовых программах.
- **Ответить всем:** добавляет в копию остальных получателей, кроме самого ящика.

Получателей можно поправить перед отправкой. В ответе:
- `In-Reply-To` — Message-ID исходного письма;
- `References` — его References плюс его Message-ID;
- тема — `Re: <тема>` (если она уже начинается с «Re:», не меняется);
- Message-ID свой, на домене ящика;
- по умолчанию внизу цитата исходного письма, её можно отключить галочкой.

Отправленное письмо сразу ложится в ленту исходящим. Gmail сам сохраняет копию в «Отправленных», и при следующей синхронизации она не задвоится: у неё тот же Message-ID. Другие серверы копию в «Отправленные» не кладут, письмо остаётся только в CRM.

## API

`GET /api/v1/deals/:id/emails` и `GET /api/v1/emails` с правом ключа `emails:read`, описание — в [INTEGRATIONS.md](INTEGRATIONS.md#e-mail).

## Переменные окружения

| Переменная | Что делает |
|---|---|
| `OPENCRM_SECRET_KEY` | Ключ шифрования паролей ящиков (любая длинная строка). Без неё используется файл ключа. |
| `OPENCRM_SECRET_FILE` | Путь к файлу ключа. По умолчанию `<каталог вложений>/../secret.key`. |
| `OPENCRM_MAIL_SYNC_SECONDS` | Интервал синхронизации, по умолчанию 120 секунд, минимум 30. |
| `OPENCRM_MAIL_INSECURE_TLS=1` | Принимать самоподписанные сертификаты. Только для локальных тестовых серверов вроде GreenMail. |
